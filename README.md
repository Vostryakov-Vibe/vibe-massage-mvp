# Салон массажа «Гармония» — сайт с онлайн-записью и CRM

Полностью рабочий проект: сайт салона массажа с онлайн-записью и
админ-панель (CRM) для сотрудников. Всё в одном приложении на Python.

Что умеет система:

| Раздел | Что делает |
|---|---|
| Лендинг | Услуги, мастера, отзывы, контакты, форма онлайн-записи с расчётом свободных окон |
| Онлайн-запись | Клиент выбирает услугу, мастера, дату и время; получает «посадочный талон» с номером записи |
| CRM (Канбан) | Все записи по статусам: новая → информирование → корректировка → подтверждена → выполнена / отменена / не пришёл. Статус меняется перетаскиванием карточки |
| Клиенты | База клиентов, рейтинг, заметки, отметка согласия на обработку персональных данных (152-ФЗ) |
| Услуги и мастера | Справочники, мягкое и жёсткое удаление, графики смен мастеров |
| Аналитика | Выручка, упущенная выгода, конверсия, средний чек, загруженность мастеров, графики + выгрузка отчёта в Excel |
| Маркетинг и ИИ | Генерация постов для соцсетей, публикация в Telegram и ВК, архив постов |
| Архив и отзывы | Скрытые услуги и мастера, отзывы для лендинга |
| Пользователи и настройки | Роли, пароли, состояние интеграций |

**Ключевая особенность: приложение работает без интернета.** Все стили, скрипты,
шрифты и картинки лежат локально в папке `static`. Интернет нужен только для
установки зависимостей и для необязательных внешних сервисов (Telegram, ВК,
капча, ИИ-генерация постов) — без них всё остальное работает в обычном режиме.

## 1. Что нужно для запуска

**Обязательно:**

* **Python 3.11 или новее** (проект проверен на Python 3.13; в Docker-образе
  используется Python 3.12). Вместе с Python ставится `pip` — программа для
  установки библиотек.
* **Свободный порт 8000** на компьютере (если занят — см. раздел 11).
* **Около 200 МБ** свободного места на диске.

**Не нужно:**

* отдельно устанавливать базу данных — используется **SQLite**, это просто файл
  `instance/salon.db`, который создаётся автоматически;
* Node.js, Docker, веб-сервер (nginx/Apache) — всё это опционально;
* постоянный доступ в интернет — нужен только один раз, чтобы скачать библиотеки
  из `requirements.txt`.

**Проверить, что Python установлен.** Откройте терминал (Windows: `Win+R` →
`cmd`; macOS: «Терминал») и выполните:

```bash
python --version
```

Ожидаемый ответ: `Python 3.13.11` (или другая версия 3.11+).

Если команда не найдена:

* **Windows** — попробуйте `py -3 --version`. Если работает, дальше вместо
  `python` пишите `py -3`. Если не работает — Python не установлен, см. шаг 1 ниже.
* **macOS / Linux** — попробуйте `python3 --version`.

## 2. Быстрый старт за 5 минут

### Шаг 1. Установить Python

* **Windows.** Скачайте установщик с [python.org](https://www.python.org/downloads/)
  и **обязательно поставьте галочку «Add python.exe to PATH»** в первом окне
  установщика. Без этой галочки команда `python` не будет работать.
* **macOS.** Скачайте установщик с [python.org](https://www.python.org/downloads/)
  или выполните `brew install python`.
* **Linux (Debian/Ubuntu).**
  ```bash
  sudo apt update
  sudo apt install python3 python3-venv python3-pip
  ```

После установки закройте и заново откройте терминал и проверьте `python --version`.

### Шаг 2. Перейти в папку с проектом

```bash
cd путь/к/папке/Mass_proj
```

Пример для Windows: `cd D:\Project\Mass_proj`.
Подсказка: в проводнике Windows можно открыть папку проекта, щёлкнуть по адресной
строке, набрать `cmd` и нажать Enter — терминал откроется сразу в нужной папке.

### Шаг 3. Создать виртуальное окружение (рекомендуется)

Виртуальное окружение — это отдельная «песочница» для библиотек проекта, чтобы
они не мешали другим программам на компьютере.

```bash
python -m venv .venv
```

Активировать окружение:

* **Windows (cmd):**
  ```bat
  .venv\Scripts\activate
  ```
* **Windows (PowerShell):**
  ```powershell
  .venv\Scripts\Activate.ps1
  ```
  Если PowerShell ругается на политику выполнения скриптов, выполните один раз
  `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и повторите.
* **macOS / Linux:**
  ```bash
  source .venv/bin/activate
  ```

Признак успеха: в начале строки терминала появилось `(.venv)`.

> Можно пропустить этот шаг и ставить библиотеки в системный Python, но тогда они
> попадут в общую систему, а на некоторых Linux-системах установка вообще
> запрещена без окружения.

### Шаг 4. Установить зависимости

```bash
pip install -r requirements.txt
```

Устанавливаются: FastAPI (веб-фреймворк), Uvicorn (сервер), SQLAlchemy (работа с
базой), Jinja2 (шаблоны), bcrypt (пароли), python-dotenv, requests (запросы к
Telegram/ВК/ИИ) и openpyxl (Excel-отчёты).

Если `pip` не найден, используйте `python -m pip install -r requirements.txt`.

### Шаг 5. Запустить приложение

```bash
python app.py
```

В консоли появится примерно такой баннер:

```text
====================================================================
  Салон массажа «Гармония» — CRM и онлайн-запись
====================================================================
  Сайт:        http://127.0.0.1:8000/
  Админка:     http://127.0.0.1:8000/admin
  API-док:     http://127.0.0.1:8000/api/docs
  База данных: sqlite:///D:/Project/Mass_proj/instance/salon.db

  Учётные записи (созданы при первом запуске):
    Суперадмин: admin / admin777
    Менеджер:   manager / manager777

  Внешние интеграции (необязательны, работают при наличии ключей в .env):
    [-] Telegram: офлайн-режим
    [-] ВКонтакте: офлайн-режим
    [-] Turnstile: офлайн-режим
====================================================================
```

> **Важно:** окно терминала должно оставаться открытым, пока вы пользуетесь
> сайтом. Закрыли терминал — сайт перестал работать.

### Шаг 6. Открыть в браузере

| Куда | Адрес |
|---|---|
| Сайт салона | <http://127.0.0.1:8000/> |
| Админ-панель | <http://127.0.0.1:8000/admin> |

## 3. Что происходит при первом запуске

Первый запуск длится на несколько секунд дольше обычного — приложение
подготавливает данные. Создаются:

1. **Папка `instance/` и файл базы `instance/salon.db`** — там хранятся все
   записи, клиенты, услуги и настройки.
2. **Учётные записи** `admin` и `manager` (пароли хранятся только в виде
   bcrypt-хэшей, восстановить их нельзя — только заменить).
3. **Системный мастер «Уволенный сотрудник»** — служебная запись, на которую
   переводятся записи при жёстком удалении мастера, чтобы история не терялась.
4. **Демонстрационные данные:** 5 услуг, 4 мастера, 12 клиентов, около 28 записей
   за последние 30 дней (выполненные, отменённые, неявки и активные на ближайшие
   дни), 6 отзывов и графики смен на 1,5 месяца вперёд.
5. **Картинки-заглушки** услуг и мастеров (SVG-файлы) в `static/uploads/`.
6. **Файл `instance/secret_key`** — ключ для подписи cookie входа. Он создаётся
   один раз и переиспользуется, поэтому вход в админку не сбрасывается после
   перезапуска сервера.
7. **Чистка архива постов** старше 30 дней (срок задаётся в `.env`).

Повторные запуски безопасны: данные не дублируются, демо-записи создаются только
если база пустая.

Чтобы получить чистую демонстрационную базу заново, остановите сервер и удалите
файлы `instance/salon.db`, `instance/salon.db-wal`, `instance/salon.db-shm` —
при следующем запуске они создадутся снова вместе с демо-данными.
**Внимание: вместе с базой удалятся все ваши записи и клиенты.**

## 4. Настройки через файл .env

Файл `.env` **не обязателен**: у всех параметров есть безопасные значения по
умолчанию, приложение запускается «из коробки». Но через него удобно менять
порт, название салона и подключать интеграции.

Как создать: скопируйте `.env.example` в `.env` и отредактируйте.

* Windows: `copy .env.example .env`
* macOS / Linux: `cp .env.example .env`

Файл `.env` — это обычный текст, по одной настройке в строке, вида `ИМЯ=значение`.
После правки перезапустите приложение (`Ctrl+C`, затем `python app.py`).

Основные параметры:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `SECRET_KEY` | генерируется и хранится в `instance/secret_key` | Ключ подписи cookie. Свой нужен при публикации в интернет |
| `HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ с других компьютеров |
| `PORT` | `8000` | Порт. Если 8000 занят, поставьте, например, `8080` |
| `DEBUG` | `false` | `true` — подробные логи и авто-перезагрузка при правке кода |
| `SESSION_HTTPS_ONLY` | `false` | Отправлять cookie сессии только по HTTPS. Включайте при публикации за HTTPS-прокси (в `docker-compose.prod.yml` включено) |
| `DOMAIN` | пусто | Домен для публикации на сервере, использует `docker/docker-compose.prod.yml`. Локальному запуску не нужен |
| `SALON_NAME`, `SALON_TAGLINE`, `SALON_ADDRESS`, `SALON_PHONE`, `SALON_EMAIL`, `SALON_HOURS`, `SALON_TELEGRAM`, `SALON_VK`, `SALON_WHATSAPP` | данные «Гармонии» | Контакты салона на сайте и в админке |
| `DEFAULT_SUPERADMIN_LOGIN` / `DEFAULT_SUPERADMIN_PASSWORD` | `admin` / `admin777` | Логин и пароль суперадмина, создаваемые при первом запуске |
| `DEFAULT_MANAGER_LOGIN` / `DEFAULT_MANAGER_PASSWORD` | `manager` / `manager777` | То же для менеджера |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | пусто | Уведомления о новых записях в Telegram |
| `VK_ACCESS_TOKEN`, `VK_GROUP_ID` | пусто | Публикация постов на стене группы ВК |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | пусто | Капча Cloudflare Turnstile в форме записи |
| `AI_API_URL` | `https://text.pollinations.ai` | Адрес бесплатного текстового API для генерации постов. Значение `local` полностью отключает интернет и включает офлайн-шаблоны |
| `AI_API_TIMEOUT` | `25` | Таймаут запроса к ИИ, секунды |
| `POSTS_RETENTION_DAYS` | `30` | Сколько дней хранить архив сгенерированных постов |
| `SLOT_STEP_MINUTES` | `30` | Шаг сетки времени для записи |
| `MIN_LEAD_MINUTES` | `60` | За сколько минут до сеанса ещё можно записаться на сегодня |
| `DATABASE_URL` | `sqlite:///instance/salon.db` | Путь к базе. Пригодится, чтобы держать базу в другом месте |

> Учётные записи создаются **только при первом запуске** (когда база пустая).
> Если поменять `DEFAULT_*` в `.env` позже, пароли уже созданных пользователей не
> изменятся — их нужно менять в админке, в разделе «Настройки».

**Пример: поменять порт на 8080 и название салона.**

```ini
PORT=8080
SALON_NAME=Салон массажа «Тишина»
SALON_PHONE=+7 (999) 000-11-22
```

После перезапуска сайт будет доступен на <http://127.0.0.1:8080/>.

## 5. Необязательные интеграции

Все они подключаются через `.env`. Без ключей приложение работает нормально:
в консоль пишется предупреждение вида «Telegram не настроен — сообщение не
отправлено, работа продолжается».

### Telegram — уведомления о новых записях

1. В Telegram напишите боту **@BotFather** команду `/newbot` и создайте бота.
2. BotFather выдаст токен вида `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`.
3. Добавьте бота в рабочую группу сотрудников (или напишите ему в личку).
4. Узнайте `chat_id`: напишите что-нибудь в чат и откройте
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` — в ответе будет
   `"chat":{"id":-1001234567890}`. Это и есть `TELEGRAM_CHAT_ID`.
5. Впишите оба значения в `.env` и перезапустите приложение.

Теперь при каждой онлайн-записи в чат придёт карточка: услуга, мастер, дата,
время, стоимость, имя и телефон клиента.

### ВКонтакте — публикация постов

Нужен токен сообщества с правом управления записями (`VK_ACCESS_TOKEN`) и
числовой id группы (`VK_GROUP_ID`). Публикация выполняется методом `wall.post`,
кнопки появляются в разделе **Маркетинг и ИИ**.

### Cloudflare Turnstile — капча в форме записи

Заполните `TURNSTILE_SITE_KEY` и `TURNSTILE_SECRET_KEY` — форма начнёт
проверять посетителя через сервис Cloudflare (нужен интернет). Если ключей нет,
работает встроенная офлайн-защита: скрытое honeypot-поле, подписанный токен
формы с проверкой времени заполнения и лимит заявок с одного IP.

### Маркетинговый ИИ

По умолчанию генерация постов идёт через бесплатное внешнее текстовое API.
Если интернета нет или сервис ответил ошибкой, приложение **само** переключается
на встроенные офлайн-шаблоны — пост всё равно будет создан, в архив пишется
источник (`ИИ-API` или `Офлайн-шаблон`). Чтобы не обращаться в интернет вообще:

```ini
AI_API_URL=local
```

## 6. Запуск в Docker

Docker позволяет запустить проект в изолированном контейнере, без установки
Python на компьютер. Нужен установленный Docker Desktop (Windows/macOS) или
Docker Engine (Linux).

Из корня проекта:

```bash
docker compose -f docker/docker-compose.yml up --build
```

После сборки сайт откроется на том же адресе <http://127.0.0.1:8000/>.

Что полезно знать:

* база данных и загруженные картинки лежат в отдельных томах (`salon-db`,
  `salon-uploads`), поэтому пересборка контейнера их не удаляет;
* ключи интеграций можно передать через файл `.env` в корне проекта или указать
  в `docker/docker-compose.yml`;
* внутри контейнера сервер слушает `0.0.0.0:8000`;
* есть встроенная проверка здоровья (`/healthz`) — Docker сам перезапустит
  контейнер, если приложение упало;
* остановить: `Ctrl+C`, удалить контейнер: `docker compose -f docker/docker-compose.yml down`,
  удалить вместе с данными: добавьте `-v`.

## 7. Проверка работоспособности (smoke-тест)

В проекте есть готовый набор проверок — 51 штука. Он проходит по всем ключевым
сценариям: открытие сайта, расчёт слотов, антиспам, создание записи, вход в
админку и роли, Канбан, аналитика, Excel-отчёт, генерация поста, справочники.

**Приложение должно быть уже запущено** (в отдельном окне терминала).

```bash
python scripts/smoke_test.py
```

Если приложение запущено по другому адресу (например, с `HOST=0.0.0.0`), адрес
можно указать явно:

```bash
SMOKE_BASE=http://192.168.1.10:8000 python scripts/smoke_test.py
```

Ожидаемый результат в конце:

```text
==============================================================
Пройдено: 51 | Провалено: 0
==============================================================
```

Если какой-то пункт упал — в отчёте будет видно, какой именно.

> Тест создаёт в базе реальные данные: клиента «Тестовый Клиент» и запись на
> несколько дней вперёд. Для демонстрационного стенда это нормально.

## 8. Структура проекта

```text
Mass_proj/
├── app.py                  Точка входа: сборка приложения, баннер, запуск сервера
├── config.py               Все настройки (читает .env, подставляет значения по умолчанию)
├── database.py             Подключение к SQLite, сессии, создание таблиц
├── models.py               Таблицы БД: пользователи, услуги, мастера, смены, клиенты, записи, отзывы, посты
├── security.py             Пароли (bcrypt), вход в сессию, CSRF, ограничение попыток
├── scheduling.py           Расчёт свободных слотов и проверка занятости
├── analytics.py            Метрики дашборда и выгрузка отчёта в Excel
├── ai_marketing.py         Генерация постов: внешнее ИИ-API + офлайн-шаблоны
```

## 10. Как пользоваться системой

### Записать клиента через сайт

1. Откройте <http://127.0.0.1:8000/> и прокрутите до блока «Онлайн-запись».
2. Выберите программу, мастера и дату — свободные окна подгрузятся автоматически.
3. Выберите время, укажите имя и телефон, отметьте согласие на обработку данных.
4. Нажмите «Записаться» — появится талон с номером записи (например, `ГРМ-000028`).

Клиент попадёт в базу автоматически, а запись — в CRM со статусом «Новая».

### Работа с записями (Канбан)

1. Админка → **Записи (CRM)**. Записи разложены по колонкам-статусам.
2. **Перетащите карточку** в другую колонку, чтобы сменить статус — изменение
   сохраняется сразу.
3. Клик по карточке открывает карточку записи: дата, время, мастер, стоимость,
   комментарий. Стоимость можно изменить вручную (например, со скидкой).
4. Кнопка создания записи пригодится, если клиент позвонил: можно выбрать
   существующего клиента или завести нового прямо в форме.
5. Если пришла новая онлайн-заявка, в открытой CRM раздаётся звуковой сигнал и
   появляется всплывающее уведомление (проверка каждые 20 секунд).

### Графики смен

Админка → **Мастера и графики** → у нужного мастера кнопка «График смен».
Задайте период, отметьте дни недели и время работы — смены создадутся пачкой.
Клиенты смогут записаться только на те дни, где у мастера есть смена.

### Аналитика и Excel

Админка → **Дашборд**. Выберите период (быстрые кнопки «Сегодня / Неделя /
Месяц» или произвольные даты). Показатели: фактическая выручка, упущенная выгода
(отмены и неявки), конверсия, средний чек, число клиентов, загруженность
мастеров. Кнопка выгрузки сохраняет отчёт `.xlsx` с шестью листами.

### Генерация постов

Админка → **Маркетинг и ИИ**: укажите тему, тональность, длину и ключевые слова,
нажмите «Сгенерировать пост». Готовый текст можно скопировать или сразу
опубликовать в Telegram/ВК (если настроены ключи). Все посты сохраняются в архиве
и автоматически удаляются через 30 дней.

## 11. Если что-то не работает

### `python` не является внутренней или внешней командой

Python не установлен или не добавлен в PATH.

* Windows: переустановите Python с галочкой «Add python.exe to PATH» либо
  используйте `py -3` вместо `python`.
* Проверьте: `py -3 --version`, `python3 --version`.
* После установки обязательно откройте **новое** окно терминала.

### `pip` не найден

Используйте вызов через интерпретатор: `python -m pip install -r requirements.txt`.
Убедитесь, что виртуальное окружение активировано (в строке терминала есть `(.venv)`).

### Ошибка при установке `bcrypt` (нужен компилятор)

На Windows иногда pip пытается собрать пакет из исходников. Помогает обновление
pip и установка готового колеса:

```bash
python -m pip install --upgrade pip
python -m pip install --only-binary=:all: -r requirements.txt
```

Если не помогло — установите «Microsoft C++ Build Tools» с сайта Microsoft.

### pip не может скачать пакеты (корпоративная сеть, прокси)

Укажите прокси или внутреннее зеркало:

```bash
pip install -r requirements.txt --proxy http://user:password@proxy-server:8080
pip install -r requirements.txt -i https://внутреннее-зеркало/simple
```

### Порт 8000 занят: `[Errno 10048] address already in use`

Запустите на другом порту, например на 8080:

* Windows (cmd): `set PORT=8080 && python app.py`
* Windows (PowerShell): `$env:PORT="8080"; python app.py`
* macOS / Linux: `PORT=8080 python app.py`

Или найдите и закройте старый процесс:

* Windows: `netstat -ano | findstr :8000`, затем `taskkill /F /PID <номер>`
* macOS / Linux: `lsof -i :8000`, затем `kill <номер>`

### Сайт открылся, но «Не удалось загрузить список мастеров», нет слотов

Скорее всего, сервер не запущен или упал. Посмотрите окно терминала с сервером:
там будет причина. Частая ситуация — терминал закрыли или нажали `Ctrl+C`.

### При входе в админку: «Слишком много попыток входа»

Это защита от подбора пароля: 10 попыток с одного IP за 15 минут. Подождите
15 минут или перезапустите приложение (счётчик сбрасывается).

### Забыт пароль администратора

Если в базе есть другой суперадмин — смените пароль через админку. Если нет,
замените хэш напрямую (в папке проекта, при остановленном сервере):

```bash
python -c "import database, models, security; from sqlalchemy import select; s=database.SessionLocal(); u=s.scalar(select(models.User).where(models.User.username=='admin')); u.password_hash=security.hash_password('НовыйПароль123'); s.commit(); print('готово')"
```

### Изменения в файлах не видны

* Проверьте, что перезапустили сервер (правки в Python-коде не подхватываются на
  лету, если `DEBUG=false`).
* В браузере обновите страницу с очисткой кэша: `Ctrl+F5` (Windows) или `Cmd+Shift+R` (macOS).

### В консоли Windows вместо русских букв «кракозябры»

Приложение само переключает вывод в UTF-8. Если вы запускаете свои скрипты —
выполните `chcp 65001` в этом окне терминала.

### Пропали стили: сайт выглядит как обычный текст

Не хватает библиотек в `static/vendor/`. Если папка пустая, скачайте их один раз
(нужен интернет):

```bash
python scripts/fetch_assets.py
```

### Нужно начать с чистой базы

Остановите сервер и удалите `instance/salon.db` (вместе с `-wal` и `-shm`, если
есть). При следующем запуске база создастся заново с демо-данными.
**Все ваши данные будут потеряны.** Перед этим сделайте копию папки `instance/`.

### Что-то ещё

Загляните в окно терминала, где запущен сервер: приложение пишет туда понятные
сообщения о каждой ошибке. Также откройте <http://127.0.0.1:8000/api/docs> —
там видно, какие есть методы API и какие данные они ожидают.

## 13. Частые вопросы

**Нужен ли интернет для работы сайта?**
Нет. Все стили, скрипты, шрифты и картинки хранятся локально. Интернет нужен
только для установки библиотек и для необязательных сервисов (Telegram, ВК,
капча, внешний ИИ).

**Нужно ли устанавливать MySQL, PostgreSQL или что-то ещё?**
Нет. Используется SQLite — база данных в одном файле `instance/salon.db`.

**Где хранятся данные и как сделать резервную копию?**
Все данные в папке `instance/` (база и ключ) и в `static/uploads/` (картинки).
Чтобы сделать копию, остановите сервер и скопируйте эти две папки.
Если сервер остановить нельзя, копируйте **все** файлы базы — `salon.db`,
`salon.db-wal` и `salon.db-shm`: база работает в режиме WAL, и без двух
последних файлов копия окажется неполной (часть данных ещё не перенесена в
основной файл).

**Сколько человек может работать одновременно?**
Приложение рассчитано на работу одного салона: несколько сотрудников в админке и
посетители на сайте. Для большой нагрузки нужен другой сервер и СУБД.

**Как изменить услуги, цены, мастеров, тексты?**
Через админку: разделы «Услуги», «Мастера и графики», «Архив и отзывы».
Контакты салона и название меняются в `.env` (переменные `SALON_*`).

**Почему на некоторых карточках услуг картинки-заглушки?**
Фотографии в проект не входят: картинки генерируются автоматически в фирменных
цветах. Можно заменить файлы в `static/uploads/` своими — имена файлов указаны в
карточках услуг и мастеров (при следующем обновлении страницы изменения
подхватятся). Если положить свою картинку с тем же именем, приложение её не
перезапишет: обновляются только собственные заглушки.

**Можно ли удалить услугу, по которой уже были записи?**
Да. Обычное удаление — «мягкое»: услуга скрывается с сайта, история сохраняется.
Жёсткое удаление (только суперадмин) тоже не портит аналитику: в записях
остаётся снимок названия услуги и имени мастера.

## 14. Публикация в интернет и безопасность

Проект рассчитан на локальный запуск, но его можно выложить на сервер. Перед
этим обязательно сделайте следующее:

1. **Смените пароли** `admin` и `manager` в админке (Настройки → Смена своего пароля).
2. **Задайте свой `SECRET_KEY`** в `.env` — длинную случайную строку.
3. **Оставьте `DEBUG=false`**, чтобы не показывать отладочную информацию.
4. **Поставьте HTTPS** (например, через nginx как обратный прокси с сертификатом
   Let's Encrypt) — иначе логины и пароли пойдут по сети открытым текстом.
5. **Закройте лишние порты**: приложение должно быть доступно только через прокси.
6. **Настройте резервное копирование** папок `instance/` и `static/uploads/`.

Полезно знать про ограничения встроенной защиты:

* ограничение частоты запросов опирается на IP-адрес из заголовка
  `X-Forwarded-For`. За обратным прокси это правильно, но при прямом доступе в
  интернет заголовок можно подделать — поэтому прокси обязателен;
* капча (Turnstile) включается только при наличии ключей, а без неё защита от
  ботов держится на honeypot-поле, токене формы и лимите заявок;
* пароли по умолчанию (`admin777`, `manager777`) известны всем, кто видел этот
  файл, — их замена обязательна.

### Как показать сайт удалённо (туннель)

Если нужно открыть сайт с другого компьютера или телефона, а выделенного сервера
нет, проще всего поднять временный туннель с этой же машины: приложение остаётся
локальным, а публичный адрес выдаёт сервис-посредник.

**Вариант 1. Через SSH — ничего устанавливать не нужно.** Клиент SSH уже есть в
Windows 10/11, macOS и Linux. В отдельном окне терминала (приложение должно быть
запущено):

```bash
ssh -R 80:localhost:8000 nokey@localhost.run
```

Сервис напечатает публичный адрес вида `https://xxxx.lhr.life` — открывайте его с
любого устройства. Остановить туннель — `Ctrl+C` в этом окне.

Так же работает альтернативный сервис:

```bash
ssh -R 80:localhost:8000 serveo.net
```

**Вариант 2. Cloudflare Tunnel** — стабильнее, но требует установки `cloudflared`:

```bash
cloudflared tunnel --url http://localhost:8000
```

**Вариант 3. ngrok** — нужен бесплатный аккаунт и токен:

```bash
ngrok config add-authtoken ВАШ_ТОКЕН
ngrok http 8000
```

**Если устройства в одной сети** (компьютер и телефон по Wi-Fi), туннель не нужен:
запустите приложение с `HOST=0.0.0.0`, разрешите порт 8000 в брандмауэре и
открывайте `http://<локальный-IP>:8000`. Адрес для других устройств приложение
печатает в баннере при запуске — строка «Сеть» (там же подсказка, что он для
других устройств). Посмотреть адрес вручную можно командой `ipconfig` (адаптер
Wi-Fi или Ethernet). Второе устройство должно быть в той же подсети — то есть его
IP должен начинаться с тех же чисел, что и у первого.

> **Важно.** Перед выходом в интернет выполните пункты 1–4 из списка выше: смена
> паролей, свой `SECRET_KEY`, `DEBUG=false`, HTTPS. Туннель выдаёт публичный
> адрес, который может найти кто угодно: пока пароли по умолчанию, любой
> посетитель войдёт в админку и увидит базу клиентов с телефонами и заметками.
> Бесплатные туннели к тому же пропускают трафик через сервис-посредник, поэтому
> для реальных персональных данных клиентов они не годятся — только для
> демонстрации. Для постоянной работы нужен свой сервер (VPS) с HTTPS: проект
> собирается в Docker одной командой, см. раздел 6.

### Публикация на своём сервере (VPS) с HTTPS

Туннель хорош для быстрого показа: он живёт, пока запущен ваш компьютер, и адрес
каждый раз новый. Для постоянного адреса нужен сервер. В проекте уже есть готовая
сборка с автоматическим HTTPS (`docker/docker-compose.prod.yml` + `docker/Caddyfile`):
Caddy сам получает и продлевает сертификат Let's Encrypt, а приложение наружу не
публикуется — снаружи виден только он.

Порядок:

1. Возьмите VPS с Ubuntu (хватит самого дешёвого) и привяжите к нему домен: у
   регистратора добавьте A-запись, указывающую на IP сервера. Откройте порты 80 и
   443 — они нужны и для сайта, и для проверки домена.
2. Установите Docker: `curl -fsSL https://get.docker.com | sh`
3. Скопируйте проект на сервер (`git clone` или `scp`) и перейдите в его папку.
4. Создайте рядом файл `.env` и заполните минимум: `DOMAIN=salon.example.com`,
   `SECRET_KEY=<длинная случайная строка>`, `DEFAULT_SUPERADMIN_PASSWORD=<свой
   пароль>`; при необходимости — ключи Telegram и ВК.
5. Запустите:
   ```bash
   docker compose -f docker/docker-compose.prod.yml up -d --build
   ```
6. Откройте `https://<ваш-домен>/admin`, войдите и смените пароли по умолчанию.

Полезно знать: база и картинки лежат в томах Docker, поэтому
`docker compose -f docker/docker-compose.prod.yml down` (без флага `-v`) их
сохраняет, а `up -d --build` после правок кода обновляет приложение без потери
данных. Логи: `docker compose -f docker/docker-compose.prod.yml logs -f`.
Обновление версии приложения сводится к `git pull` и повторному `up -d --build`.
